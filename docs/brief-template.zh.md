# 《行旅旨意》需求解析模板 + 六部任务单模板（v0.1 草案）

> 辐条契约（墙4）：所有部门共享同一份《旨意》，六部任务单全部引用旨意 ID，避免各说各话。

---

## A. 前端表单字段（一次性填表）

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 出发地 | ✅ | 城市选择/输入 | 支持「成都」「成都双流机场」「成都东站」粒度 |
| 目的地 | ✅ | 城市选择/输入 | 多目的地？内测版先只支持单目的地（往返），中转城市由系统建议 |
| 出行天数 | ✅ | 数字 | 含往返日，如「3天2晚」 |
| 预算（元/人） | ❌ | 区间滑杆 | 0~20000，可只填上限或只填下限 |
| 旅游风格 | ❌ | 滑杆 | 特种兵 ────────── 佛系（默认中间） |
| 同行人 | ❌ | 多选+数字 | 独自/情侣/朋友（几人）/家人（几人）/带老人/带小孩（几岁） |
| 大概日期 | ❌ | 日期或季节 | 「8月下旬」「国庆」「明年春节」均可 |
| 兴趣偏好 | ❌ | 多选标签 | 自然风光/人文历史/美食/购物/亲子/网红打卡/小众 |
| 备注 | ❌ | 自由文本 | 「想去三星堆」「不吃辣」等 |

**追问规则（太子）：** 只有以下情况才追问（最多 2 问，合并为一轮）：
- 无日期且无季节 → 问「大概什么时候去？」
- 有小孩但未写年龄 → 问「孩子几岁？」
- 预算为 0 且风格为特种兵 → 问「预算上限大概多少？」
其余缺失一律用默认值，不再问。

## C. 六部任务单模板（尚书签发）

每部收到：旨意全文 + 本部分工 + 输出文件路径 + 溯源要求。

```
=== 户部任务单 ===
旨意编号: YZ-20260814-001
任务: 按《旨意》核算「成都→重庆 3天2晚」分项预算
要求:
1. 分项: 交通(往返大交通+市内)/住宿(2晚)/餐饮(3天)/门票/应急金(总预算10%)
2. 每项给出: 低档/中档/高档三档价格，以及你选的推荐档
3. 每个数字必须标注: 来源(URL或站点) + 查询时间 + ✅实查/📊估算
4. 输出到: C:\...\workspace\travel-planner\jobs\YZ-20260814-001\hubu-budget.md
5. 查不到价格的项写「📊估算区间」并注明估算依据
```

其余五部同构，分工见 ARCHITECTURE.md §2.2。

## E. 交付方案页（plan.html）区块顺序

1. 顶部总览卡：目的地/天数/预算达成度/风格匹配度/同行适配评分
2. 方案 Tab（2-3 套）：经济型 / 均衡型 / 舒适型
3. 每套方案：
   - 行程总览（每日一卡：上午/下午/晚上 + 动线）
   - 交互地图（景点标记 + 每日路线连线 + 点击弹详情）
   - 每日时间轴（时间-事项-交通方式-耗时-费用）
   - 住宿建议（区域+推荐档位+溯源）
   - 分项预算表 + 总预算 + 与用户预算对比条
   - 利弊清单（✅亮点 / ⚠️坑点 / 👥适合人群）
   - 溯源标签（每个数字可点开看来源）
4. 底部：三套方案并排对比表
5. 修改意见输入框 → 局部重新派单
